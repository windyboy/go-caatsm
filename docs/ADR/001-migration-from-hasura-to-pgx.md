# ADR-001: Migration from Hasura to pgx

## Status
Accepted

## Context
The current system uses Hasura GraphQL API as an intermediary layer between the Go application and PostgreSQL database. While Hasura provides automatic GraphQL API generation and real-time subscriptions, it introduces several challenges:

1. **Additional Dependency**: Hasura requires a separate service to run and maintain
2. **Performance Overhead**: GraphQL layer adds latency compared to direct database access
3. **Limited Control**: Less control over query optimization and database-specific features
4. **Complexity**: Additional configuration and deployment complexity
5. **TimescaleDB Integration**: Direct database access is required to leverage TimescaleDB features effectively

## Decision
We will migrate from Hasura GraphQL API to direct PostgreSQL access using `pgx/v5`, a high-performance PostgreSQL driver for Go.

## Consequences

### Positive
- **Performance**: Direct database access eliminates GraphQL overhead
- **Control**: Full control over SQL queries and database features
- **Simplicity**: One less service to deploy and maintain
- **TimescaleDB**: Direct access to TimescaleDB-specific features (hypertables, continuous aggregates, compression)
- **Type Safety**: Better type safety with Go structs
- **Flexibility**: Easier to implement complex queries and optimizations

### Negative
- **API Development**: Need to implement REST API endpoints manually (previously auto-generated by Hasura)
- **Real-time Features**: Need to implement real-time features using other mechanisms (e.g., WebSockets, Server-Sent Events)
- **Schema Management**: Need to manage database migrations manually
- **Code Maintenance**: More code to maintain for data access layer

### Mitigation
- Use Echo framework for REST API implementation
- Implement proper migration system using `golang-migrate`
- Create comprehensive repository layer with proper abstractions
- Document API endpoints using OpenAPI/Swagger

## Implementation Notes
- Repository pattern will be used to abstract database access
- All database operations will use `context.Context` for cancellation and timeouts
- Connection pooling will be configured for optimal performance
- Transactions will be used for batch operations
